# Описание проекта

Это веб-сервер, который реализует функциональность простейшего планировщика задач. Аналог TODO-листа. 
Планировщик хранит задачи, каждая из них содержит дату дедлайна и заголовок с комментарием. Задачи могут повторяться по заданному правилу: ежегодно или через какое-то количество дней.
Если отметить такую задачу как выполненную, она переносится на следующую дату в соответствии с правилом. Обычные задачи при выполнении удаляются.

## Используемый стек

в проекте используется следующий стек технологий и компонент:
- goLang `v.1.23`
- sqlite `v.3.40`


# Список выполенных заданий со звёздочкой

Выполнены следующие задания повышенной сложности:
1. Реализована возможность определять извне порт при запуске сервера через переменные окружения.
2. Реализована возможность определять путь к файлу базы данных через переменную окружения. 
3. Добавлена возможность выбрать задачи через строку поиска (список задач на основе текста, используя поля title и comment или на кокретную дату)
4. Создан докер образа.


# Инструкция по запуску кода

## Конфигурация проекта

Для изменения конфигурации требуется создать в корне папки проекта текстовый файл `.env`, который включает в себя локальные  переменные:

```bash
# Порт, который "слушает" приложение
TODO_PORT=7540
# Путь к файлу с базой данных (sqlite)
TODO_DBFILE=./scheduler.db
```

**NB:** Так же можно прописать переменные окружения ОС, они будут обладать более высоким приоритетом (чем параметры в файле .env), например:

```bash
#!/bin/bash
$ TODO_PORT=7540
$ TODO_DBFILE=./scheduler.db
```

## Локальный запуск
Для запуска потребуется установленный в системе `golang v.1.23`.

Пример запуска для MacOSx:

```bash
#!/bin/bash
$ cd PATH_TO_PROJECT
$ go run main.go
```
Приложение будет доступно по адресу http://localhost:7540

## Запуск на удаленном сервере
Для запуска на удаленом сервере, в системе должно быть установлено ПО Docker, и образ проекта.

### Сборка образа проекта (Docker)
Для сборки образа выполните команды:

```bash
#!/bin/bash
$ cd PATH_TO_PROJECT
$ docker build --tag my-app:v1 .
```

### Запуск контейнера
Если контейнер уже доступен на удаленном сервере, просто запустите его, выполнив команды:

```bash
#!/bin/bash
$ docker run -d -p 7540:7540 my-app:v1
```

где `7540` адрес пробрасываемого порта приложения из docker-образа в ОС (для переопределения см.пункт `Инструкция по запуску кода` → `Конфигурация проекта`)
